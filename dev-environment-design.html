SEC 01

設計思想

開発に関わる状態(リポジトリ・ランタイム・Docker・シークレット・作業セッション)はすべて Mac mini の一箇所にのみ存在させる。MacBook Pro は表示と入力を担う端末であり、紛失・故障・買い替えのいずれが起きてもキッティングキット(SEC 09)により 15〜20 分で復旧できる状態を維持する。

MBP には 「宣言的に再現できるもの」 と 「アカウントで同期されるもの」 だけを置く。
手で設定するもの・手で同期するものは一切置かない。

SEC 03

配置計画 — どこに何を置くか

Mac mini は書斎デスクに直置きし、Dell と USB-C/Thunderbolt で直結する。

クローゼットのラックからデスクへ映像を引くと、パッシブ TB/USB-C ケーブルは 4K60 で実質 1〜2m が限界。光ファイバー式なら届くが 2〜5 万円かかり、得るものは「デスクから小箱が消える」だけ。mini は静音・小型でデスク置きのデメリットがほぼない。

決
MacBook Pro の定位置はリビングとする。

充電環境は「使う場所」に置くのが原則。リビング使用が最多である以上、書斎定位置では「取りに行く・戻す」の摩擦が毎回発生する。書斎に MBP の常設場所を作らないことで「書斎 = mini ネイティブ / それ以外 = MBP」の役割分担が空間側でも固定される。

決
場所置くもの設備・備考
書斎デスク Mac mini + Dell 27" USB-C 1本で映像 + ディスプレイ内蔵ハブ。Dell が USB-C 給電対応なら、MBP 持込時は同じケーブルを挿し替えるだけで給電(65〜90W)+ 外部画面になる → 書斎の予備充電ケーブルはディスプレイが兼任。
弱電クローゼット ネットワーク機器のみ UCG Fiber・Pro Max 16 PoE・UPS。mini は置かない。デスクへは Cat6A 1本を落とすだけ。
リビング MBP 定位置 65–70W USB-C 充電器 + ケーブル常設。閉じて置ける棚・ワゴンを一箇所決める。新居では造作・コンセント計画に組込み。
カバン MBP(外出時) 持ち出すのは MBP と充電器のみ。鍵・秘密情報は物理的に持ち歩かない(1Password + mini 側保持)。

帯域設計: Remote SSH は数百Kbps、画面共有 4K でも ~75Mbps のため 1GbE で十分。将来 NAS を導入し大容量転送が日常化する場合のみ、mini の 10GbE BTO を検討(配線は Cat6A 済みで対応可能)。

SEC 04

使い分け判断表 — いつ mini、いつ MBP

判断基準はシンプルに一つ:「書斎のデスクに座るか否か」。座るなら mini をネイティブで、それ以外はすべて MBP から mini へリモート。実行される場所は常に mini である。

デプロイ・長時間処理・データ移行どちらでもtmux 内で実行MBP を閉じても mini で続行。切断事故が構造的に消える。

SEC 05

エンドツーエンド運用シナリオ(平日の一例)

  • 07:30リビング
    MBP でメール・Slack・軽い確認

    定位置から開くだけ。開発に触れるなら ssh mini → tmux attach で昨夜の続きが出る。

  • 09:00書斎
    mini ネイティブで集中開発ブロック

    Dell 直結。tmux 配置は固定(win1: レセまる / win2: Gisium)。Docker・DB は mini で常時起動のため「毎朝 compose up」の儀式は存在しない。MBP はリビングに置いたまま。

  • 12:30リビング
    昼食後、MBP で続きから

    mini は放置でよい。tmux attach で実行中の dev サーバー・ログがそのまま。動作確認はブラウザで http://mini:3000。

  • 14:00オフィス
    出社。手順は宅内と完全に同一

    Tailscale は張りっぱなしなので切替操作なし。Milhan とのレビュー・ペア作業も MBP に映るのは mini の環境 = 普段と同じもの。重いテストを回しても MBP は発熱せずバッテリーも減らない。

  • 17:00オフィス
    デプロイ(レセまる: 11〜25日の安全窓のみ)

    必ず mini の tmux 内で実行。開始したら MBP を閉じて退社してよい — 処理は mini で続行し、帰宅後に同じセッションで結果を確認。レセプト・フリーズ(1〜10日)中はリリース作業自体を行わない。

  • 21:00リビング
    夜: 軽い作業 or 読書

    コードを触るなら同じく ssh mini。Kindle / Books はローカルで完結。終わったら定位置に置いて充電 — 翌朝も満充電で始まる。

  • 前夜出張・帰省前
    オフライン準備(所要1分)

    git -C ~/repos/… pull だけ。機内では MBP ローカルで読み書き・mise の Node で軽い実行。着陸後に push して以後の実行は mini へ。

非日常シナリオ

イベント対応
MBP 紛失・故障・買い替え失われる状態はゼロ。新機で bootstrap.sh(SEC 09)→ ログイン5件 → 15〜20分で完全復旧。旧機はリモートワイプ or 消去して売却。
mini 障害単一障害点であることは自覚的に許容。緩和策: リポジトリは常に GitHub に push 済み + dotfiles で環境は宣言済みのため、代替機(MBP 含む)で数時間で再構築可能。Time Machine を外付け SSD に常時稼働させ、ローカルデータも保全。
自宅停電・回線障害UPS + 停電後自動起動で無人復旧。外出中に mini へ届かない場合は MBP のローカル clone でオフライン運用に切替。
mini 買い替え(数年後)chezmoi + mise + Brewfile(mini 用)で新機を宣言的に再構築。データは Time Machine 復元 or リポジトリ再 clone。
SEC 06

接続経路 — 3モード

MODE A / 書斎デスク
ネイティブ

mini + Dell 直結。リモートを介さないフル性能。最長の集中作業はここで行う。

MODE B / 宅内(リビング等)
LAN 越しリモート

ssh mini → tmux、または VS Code Remote SSH。GUI は画面共有(高パフォーマンスモード)。遅延は体感ゼロ。

MODE C / オフィス・外出先
Tailscale 経由

手順は MODE B と完全に同一。切替操作は存在しない。

GUI 接続の仕様: 高パフォーマンスモードは mini 側に仮想ディスプレイを生成して接続するため、Dell に映る画面を奪い合わない(家族が Dell を使用中でも別セッションで作業可)。ヘッドレス期間でも HDMI ダミープラグ不要。必要帯域は 4K で ~75Mbps。作業の連続性は tmux が担保: 書斎で中断 → リビングで tmux attach → 続きが表示される。

SEC 07

VPN 経路ポリシー — Tailscale と Proton の棲み分け

Tailscale(自分のデバイス同士を繋ぐ私設網)と Proton VPN(インターネット出口の変更 = ジオ変更)は役割が異なる。原則は「家中は素の回線。指定デバイスだけ VPN」— 全戸常時 VPN は遅延増に加え、銀行・行政・オンライン請求系が海外 IP を弾くため採用しない。

テレビの海外版 Netflix 視聴は、UCG Fiber の VPN Client + Traffic Route で実現する。

UniFi ゲートウェイ公式機能(Policy-Based Routing)。Proton の WireGuard 設定を UCG にインポートし、テレビ1台の全通信だけをトンネルへ振り分ける。テレビ側の設定は一切不要で機種を問わない。

決
対象方式ワンクリック切替備考
テレビ UCG Fiber: Proton WireGuard トンネル + Traffic Route(デバイス単位) UniFi アプリでルートを有効/無効 国別に複数トンネル(US/UK 等)を作り、使う方をオンにできる。Apple TV なら Proton ネイティブアプリでも代替可。
MBP Proton アプリ常駐・普段オフ メニューバーからワンクリック 動画視聴時のみ接続。接続中は mini 作業をしない(Tailscale が中継経由に落ちる場合があるため)。macOS のスプリットトンネリングは実験的機能につき依存しない。
MBP(公衆 Wi-Fi 保護) mini を Tailscale exit node に Tailscale メニューからワンタップ 全通信が WireGuard 暗号化で自宅経由に。出口 IP が自宅固定のため銀行系で弾かれにくい。Proton 不要・追加コストゼロ。
mini・その他全デバイス 素の回線(VPN なし) — 開発・業務・オンライン請求系は常に国内 IP から。
  • Proton 有料プラン契約 + WireGuard 設定を国別に生成ストリーミング対応と WireGuard 設定ダウンロードは有料プランが必要。まず US 1本から。
  • UCG Fiber に VPN Client としてインポート設定 → VPN → VPN Client。トンネルは常設でよい(ルートをオフにすれば未使用)。
  • Traffic Route: テレビ → Proton トンネルデバイス単位で紐付け。ドメイン単位の振り分けは使わない — 配信側が複数ドメインで位置情報をクロスチェックするため、部分的な VPN 経由は矛盾検出されやすい。デバイス丸ごとが確実。
  • 動作確認 + ブロック時の運用テレビで Netflix の地域が変わることを確認。VPN IP がブロックされたら Proton 側で別サーバーの設定を再生成して差し替え(いたちごっこは仕様として許容)。

SEC 09

キッティング — MBP 買い替えを無痛にする

GitHub の dotfiles リポジトリに bootstrap.sh / Brewfile / chezmoi 設定を集約(別添キット参照)。移行アシスタントは使わず、毎回クリーンセットアップとする。

Phase所要内容
1 手動~5分macOS 初期設定 + Apple ID ログインのみ。
2 自動~10分 放置curl -fsSL …/bootstrap.sh | bash — Homebrew → Brewfile 一括導入 → chezmoi 展開 → mise。冪等のため既存機の同期にも使用可。
3 手動~5分ログイン5件: 1Password(SSH エージェント有効化)/ Tailscale / ブラウザ / Kindle / エディタ Sync。
4 確認~1分ssh mini → 1Password が認証ダイアログを出せば完成。
SEC 10

Mac mini 初期設定チェックリスト

  • スリープ完全無効システム設定 → エネルギー。「ディスプレイオフ時にスリープさせない」を有効化。
  • 停電・電源断後の自動起動 ON「停電後に自動的に起動」を有効化。無人復旧の生命線。
  • リモートログイン(SSH)+ 画面共有を有効化画面共有は高パフォーマンスモード対応を確認。
  • Tailscale 導入・MagicDNS 確認宅内・宅外(テザリングでテスト)の両方から ssh mini 到達を確認。
  • FileVault 方針の決定有効のままだと遠隔再起動時にロック解除が必要。自動ログイン運用とのトレードオフを決める。
  • 1Password 公開鍵を authorized_keys に登録これで全 MBP が「1Password ログイン = mini に入れる」状態になる。
  • chezmoi で dotfiles 展開 + tmux 常用化tmux.conf は MBP と共通。デフォルトセッションを1つ決め、全作業をその中で行う。
  • Tailscale exit node として広告(advertise)MBP の公衆 Wi-Fi 保護用(SEC 07)。管理画面で exit node を承認しておく。
  • Time Machine(外付け SSD)mini 単一障害点の緩和。常時接続で自動バックアップ。
SEC 11

運用3原則

  • コードと実行は常に miniMBP ローカルでのうっかり実行が最大の混乱源。tmux ステータスバーのホスト名表示を保険とする。例外はオフライン時のみ。
  • MBP への追加は Brewfile 経由のみ手でインストールしたら負け。リストとマシンの状態を常に一致させる。
  • 作業はすべて tmux セッション内素の SSH セッションは切断で消える。tmux 内なら切断・移動・蓋閉じのすべてが「中断」でなく「継続」になる。
