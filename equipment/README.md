# 設備仕様くらべ

キッチン・洗面台・浴室の候補をブランド横断で比較し、優先度と採用を決めるための1ファイルのツール。
データは `data.json` ひとつ。Git で履歴を残す前提の形式にしてある。

visualizer リポジトリの `equipment/` に置いてある（ルートの `index.html` は別物の入口ページ）。

```
equipment/
├── index.html   # ツール本体（依存なし・ビルド不要）
├── data.json    # 比較データ。これだけをコミットしていく
└── README.md
```

## 使い方

### ローカル（Chrome / Edge）

`equipment/index.html` を直接開き、「JSONファイルに保存」でリポジトリ内の `data.json` を指定する。
以降は編集するたびにそのファイルへ直接書き込まれるので、あとは普通に

```bash
git add equipment/data.json && git commit -m "キッチン: トクラスの見積を入力"
```

次回以降はファイルを自動で読み込む。ブラウザの仕様で、開き直した直後だけ
青い帯の「ファイルを開く」を一度押す必要がある。

`file://` では `data.json` の自動読み込みができないので、確実にやるなら:

```bash
python3 -m http.server 8000   # → http://localhost:8000/equipment/
```

### GitHub Pages（閲覧のみ）

Settings → Pages でブランチを公開すると、`data.json` を自動で読み込んで表示する。
スマホでもショールームでそのまま開ける。

**公開先では編集できない。** セルの書き込み、候補・項目・部屋の追加と削除、優先度の変更、
採用の切り替えはすべて無効になり、上部に「閲覧モード」と出る。
公開先で編集できてしまうと、リポジトリに入らない変更がブラウザの中だけに溜まって
どちらが正か分からなくなるため。編集は手元のリポジトリで行い、`equipment/data.json` をコミットする。

判定は「`file://` か localhost なら編集可、それ以外は閲覧のみ」。
スマホから一時的に直したいときだけ `?edit=1` を付ける。この場合も書き込み先はブラウザ内で、
リポジトリに入れるには「GitHubで更新」で JSON をコピーしてコミットする必要がある。
この抜け道が不要なら `equipment/index.html` の `READONLY` の行から `QS.get('edit') !== '1'` を外す。

### 未保存の表示

`data.json` に入っていない編集があるあいだ、画面上部に黄色い帯が出たままになる。
帯はスクロールしても消えず、件数と行き先（`data.json`）を出す。タブのタイトルも `● 未保存` になり、
そのままページを閉じようとするとブラウザが確認する。

「GitHubで更新」または「ダウンロード」を押すと帯は緑に変わり、
*コピーはしたが、まだコミットされていない* 状態であることを示し続ける。
消えるのは、ローカルで `data.json` に直接書き込めたときだけ。

リポジトリの構成が推測と違う場合はクエリで指定できる:

```
?repo=owner/name&branch=main&path=equipment/data.json
```

読み込むファイルを変えたいときは `?data=2027-plan.json`。

### 部屋を名指しで開く

`#部屋名` を付けると、その部屋のタブを開いた状態で始まる。総括は `#総括`。

```
equipment/index.html#キッチン
equipment/index.html#お風呂
equipment/index.html#総括
```

部屋名の一部でも拾う（`#洗面` → `1階 洗面台`）。見つからない名前は無視して先頭の部屋を出す。
タブを切り替えるとハッシュも追従するが `replaceState` なので、戻るボタンは呼び出し元のページに返る。
ルートの `index.html` の入口カードは、この形で部屋ごとに直接リンクしている。

### 読み込みの優先順位

`savedAt` が一番新しいものを採用する（同着なら ローカルのファイル > リポジトリ > ブラウザ内の下書き）。
リポジトリ側を正にしたいときは「リポジトリ版に戻す」。

## data.json の形

値は項目IDではなく **項目名をキー** にしてあるので、`git diff` がそのまま読める。

```json
{
  "name": "キッチン",
  "priority": "高",
  "fields": [
    { "label": "デッド収納の使い方", "type": "long", "priority": "高" }
  ],
  "candidates": [
    {
      "name": "トクラス",
      "adopted": true,
      "values": { "金額": 1450000, "デッド収納の使い方": "コーナーは回転棚" }
    }
  ]
}
```

`type` は `money` / `text` / `long` / `tri`（`○` `△` `✕` `？` の4値。`？` は未確認）/ `rating`（0-5）。
`priority` は `高` / `中` / `低`。空の値は書き出さないので、埋まった項目だけが差分に出る。

エディタで直接書いても構わない。項目名を変えるときは `fields` と `values` の両方を直すこと。
